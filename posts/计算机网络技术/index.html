除此之外，人类还有多个网络项目，但最终美国的ARPANET胜出，成为今天的互联网

计算机网络的定义

以能够相互共享资源的方式互联起来的自治计算机系统的集合。这一定义可以从以下4个方面来理解:

  1. 计算机网络建立的主要目的是实现资源共享
  2. 互联的计算机是分布在不同地理位置的多台独立的“自治计算机”
  3. 连网计算机之间的通信必须遵守共同的网络协议
  4. 互联计算机之间的连接需要有一条通道,即由传输介质实现物理互联

网络体系结构（OSI七层 vs TCP/IP四层 vs 五层参考模型）

OSI参考模型

​ 基于国际标准化组织(International Standards Organization,ISO)1983年开发的提案提出了OSI(Open Systems Interconnection)参考模型,并在1995年修订。

​ OSI七层模型：

层 名称 英文 功能 数据单位 典型设备/协议
7 应用层 Application Layer 为用户提供网络应用服务，用户与网络的接口 报文 HTTP、FTP、SMTP、DNS、Telnet
6 表示层 Presentation Layer 数据格式转换、加密解密、压缩解压缩 报文 JPEG、MPEG、ASCII、SSL/TLS
5 会话层 Session Layer 建立、管理和终止会话连接 报文 RPC、NetBIOS、SSL
4 传输层 Transport Layer 端到端的可靠传输、流量控制、差错恢复 数据段/报文段 TCP、UDP
3 网络层 Network Layer 路由选择、寻址、分组转发 数据报/分组 IP、ICMP、路由器、三层交换机
2 数据链路层 Data Link Layer 相邻节点间的可靠传输、帧同步、差错控制 帧 MAC、交换机、网桥、PPP
1 物理层 Physical Layer 透明传输比特流、定义电气/机械/功能特性 比特 网卡、集线器、中继器、网线

一定要把这OSI参考模型背下来！（物数网传会表应）

当主机A给主机B发送消息时，通常是**：消息在主机A从上到下，传送给主机B，然后消息在主机B从下到上进行传递。**

每一层之间可以通过不同通信协议来通信，只是从逻辑上来讲两个设备的层之间可以相互通信，但实际上他们依然需要从上到下或从下到上地进行传递。

服务是值一层向它的上一层提供的一组原语(操作)(一定是下一层对上一层提供服务，不能反)

OSI参考模型的问题

由于OSI参考模型推出时，TCP/IP已经广泛部署，加上其自身存在以下问题，导致OSI七层模型并没有被真正广泛应用：

问题 说明
时机错误 OSI标准制定时，TCP/IP已经在全球大面积部署，标准来得太晚
设计问题 会话层和表示层在实际应用中几乎为空，很少有独立协议对应这两层
分层过细 数据链路层和物理层划分过于复杂，物理层包含大量不同的物理介质标准
实现复杂 七层模型过于理想化，实现起来效率低，不如TCP/IP的简洁四层模型实用
TCP/IP模型

TCP/IP实际上合并了某些层级，将OSI七层模型合并为四层。

TCP/IP模型最早实现之一是作为Berkerley Unix的一部分,尤其是学术界都把TCP/IP看成是Unix的一部分。

TCP/IP模型虽然是当今互联网的实际标准，但它在设计上也存在一些问题和局限性。

问题 说明
概念不清晰 TCP/IP模型没有明确区分服务、接口和协议这三个关键概念
通用性差 TCP/IP模型是专门为TCP/IP协议栈设计的，不适用于描述其他协议栈（如蓝牙、ZigBee等）
链路层定义模糊 TCP/IP模型中的网络接口层并不是通常意义的一层，它只是一个接口（规定了如何接入网络），而真正意义上的“层”应该包含完整的协议和功能
物理层缺失 TCP/IP模型没有区分物理层和数据链路层，将两者合并为“网络接口层”。对于有线以太网可能够用，但对于无线网络、光纤等物理介质差异较大的场景，这个设计就显得不够精细
协议固化 早期自主实现的协议已经被广泛部署，导致其他协议（如IPv6）难以取代现有协议，形成“赢家通吃”的局面
五层参考模型

由于OSI七层模型过于理论化、TCP/IP四层模型又过于简化（物理层与链路层未区分），在实际教学和工程实践中，通常采用 五层参考模型 作为折中方案。

五层参考模型综合了OSI的严谨分层思想和TCP/IP的简洁实用性，是目前计算机网络教材中最常用的教学模型。

层级 名称 英文 对应OSI层 对应TCP/IP层 功能 数据单位 典型协议/设备
5 应用层 Application Layer 应用层 + 表示层 + 会话层 应用层 为用户提供网络应用服务 报文 HTTP、FTP、SMTP、DNS
4 传输层 Transport Layer 传输层 传输层 端到端的可靠传输 数据段 TCP、UDP
3 网络层 Network Layer 网络层 网络层（网际层） 路由选择、寻址、分组转发 数据报 IP、ICMP、路由器
2 数据链路层 Data Link Layer 数据链路层 网络接口层 相邻节点间的可靠传输 帧 MAC、交换机、网桥
1 物理层 Physical Layer 物理层 （未区分，合并进网络接口层） 透明传输比特流 比特 网卡、集线器、中继器

计算机网络性能度量指标

时延（Delay）

时延是指数据（一个报文或分组）从网络（或链路）的一端传送到另一端所需的总时间，也称为延迟或迟延。时延由以下四个部分组成：

时延类型 含义 影响因素
传输时延（发送时延） 数据从结点进入传输媒体所需的时间，即发送数据帧所需的时间 数据帧长度、发送速率
传播时延 电磁波在信道中传播一定距离所花费的时间 信道长度、信号传播速度
处理时延 主机或路由器收到分组后，为处理分组（如分析首部、提取数据、差错检验、查找路由）所花费的时间 硬件性能、路由器负载
排队时延 分组在路由器输入/输出队列中排队等待处理所经历的时延 网络拥塞程度、队列长度

总时延 = 传输时延 + 传播时延 + 处理时延 + 排队时延

时延抖动（Jitter）

时延抖动是指时延的变化。由于网络中的队列或缓冲区状态不断变化，分组经历的网络时延会随时间而波动，这种变化称为抖动。

时延抖动的特点：

  • 起源于网络中的队列或缓冲机制
  • 难以精确预测（受网络流量动态变化影响）
  • 对语音、视频等实时多媒体业务影响显著，抖动过大会严重影响用户体验
往返时延（RTT，Round-Trip Time）

往返时延是指从发送方发送数据开始，到发送方收到来自接收方的确认，所经历的总时间。

RTT的主要应用：

  • 判断网络的通断性
  • 测试网络时延
  • 计算数据包丢失率
  • TCP协议中用于超时重传时间的计算
吞吐量（Throughput）

吞吐量是指单位时间内通过某个网络（或信道、接口）的数据量，单位为 b/s（bit/s）。

概念 定义 说明
吞吐量 单位时间内通过某网络的数据量 反映网络的实际数据传送能力
有效吞吐量（Goodput） 单位时间内，目的地正确接收到的有用信息量 不包括重传数据、协议开销等无效数据
利用率（Utilization）
概念 定义
信道利用率 某信道有百分之几的时间是被利用的（即有数据在传输）
网络利用率 全网络的信道利用率的加权平均值

注意：利用率并非越高越好。当利用率接近100%时，意味着网络处于拥塞状态，排队时延会急剧增大，反而导致网络性能严重下降。

丢包率（Packet Loss Rate）

丢包率是指所丢失的数据包数量占所发送数据包总数的比率。

丢包率=丢失的数据包数发送的数据包总数丢包率=发送的数据包总数丢失的数据包数

丢包的主要原因：

  • 网络拥塞导致路由器队列溢出
  • 传输过程中的比特差错
  • 路由器处理能力不足
  • 链路故障
各指标之间的关系
指标 关联说明
时延 与 时延抖动 时延抖动是时延的变化量，多媒体业务对抖动更敏感
吞吐量 与 丢包率 当网络拥塞时，吞吐量下降，丢包率上升
利用率 与 排队时延 利用率升高 → 排队时延增大 → 总时延增大
RTT 与 时延 RTT ≈ 发送方到接收方的时延 + 接收方到发送方的确认时延

数字调制

​ 为了发送数字信息,必须设法使用模拟信号表示比特(数字信息)。比特与代表它们的信号之间的映射过程称为数字调制。

​ 模拟信号是连续的：例如连续变化的电压，光照强度，声音强度

码元：码元就是数字调制过程中用来承载信息的基本信号单位，它通过特定的映射关系，将一组比特与一个独特的信号状态对应起来，从而实现数字信息的传输。

波特率与比特率
概念 定义 单位 关注点
波特率 单位时间内传输的码元个数 波特（Baud） 物理信号的变化频率，反映底层通信速率
比特率 单位时间内传输的比特个数 bit/s（bps） 实际传输的数据量，反映有用信息的速率

波特率描述的是物理层信号波形的变化速率，即每秒钟信号状态发生变化的次数。例如，一个码元可以携带1个或多个比特的信息。当每个码元仅携带1个比特时，波特率与比特率数值相等；当每个码元携带多个比特时，比特率 = 波特率 × 每个码元携带的比特数。

比特率描述的是实际传输的有用数据速率，即每秒钟从发送端到接收端成功传输的比特数量。它反映了网络传输数据的实际效率。

$$比特率 = 波特率 \times \log_2 N$$

其中，N 为一个码元所含的状态数（即一个码元可以取 N 种不同的离散值）。

场景 波特率 每个码元比特数 比特率
二进制传输（N=2） 1000 Baud 1 bit 1000 bit/s
四电平传输（N=4） 1000 Baud 2 bit 2000 bit/s
八电平传输（N=8） 1000 Baud 3 bit 3000 bit/s
数字调制方法

将数字信号调制成模拟信号，有调幅、调频和调相三种方式。

QAM 正交振幅调制

QAM（Quadrature Amplitude Modulation，正交振幅调制）是在频率相同的前提下，将调幅（AM） 和 调相（PM） 相结合，形成叠加的调制信号。

$$\text{比特率} = \text{波特率} \times \log_2 ({相位数} \times {振幅数})$$

奈奎斯特定理

在无噪声的理想信道中，码元传输速率存在一个上限值，该上限由信道带宽决定：

$$B = 2H$$

H位信道的带宽，即信道传输上、下限频率差值，单位为Hz

无噪声下信道传输能力：

$$C = B \log_2 N \quad (\text{b/s})$$

其中：

  • C为信道传输能力（比特率），单位为 b/s
  • B为波特率（码元传输速率），单位为 Baud
  • N为码元可取的离散电平数（状态数）
香农公式

$$C = H \log_2 \left( 1 + \frac{S}{N} \right)$$

其中：

符号 含义 单位
C 信道最大传输速率（信道容量） bit/s（bps）
H 信道带宽 Hz
S 信号功率 W
N 噪声功率 W
S/N 信噪比 无量纲（倍数）
信噪比分贝

信噪比（Signal-to-Noise Ratio，SNR）是信号功率与噪声功率的比值。在工程上，信噪比通常用分贝（dB） 来表示，其换算关系为：

$$\text{信噪比(dB)} = 10 \lg \left( \frac{S}{N} \right)$$

其中，SS 为信号功率，NN 为噪声功率。分贝值常用于衡量信号质量，数值越大表示信号相对噪声越强。

信道复用技术

信道复用（Channel Multiplexing）是指在有限的物理信道资源上，通过不同方式让多个信号共享同一个信道，以提高资源利用率和通信效率。对物理信道进行复用主要有三种方法：频率、时间和编码。

常见的信道复用技术有**：频分复用**、时分复用、码分复用，此外还有一种称为波分复用，本质上是频分复用的光学形式。

频分复用（FDM，Frequency Division Multiplexing）

频分复用将信道的可用频谱划分为多个互不重叠的频率子带（频段），每个子带分配给一个独立的信号使用。信号在频域上并排分布，互不干扰。

比如收音机，同时接收各种不同的频段，通过解析不同的频率来换台。

优点 缺点
技术成熟，实现简单 频带利用率相对较低，存在保护带的开销
各信道之间隔离度高，干扰小 频谱资源固定分配，灵活性差
适合模拟信号传输 频带划分后难以动态调整带宽
时分复用（TDM，Time Division Multiplexing）

时分复用将时间划分为若干个等长的时隙（Time Slot），每个时隙轮流分配给不同的信号使用。信号在时间上顺序排列，互不重叠。

比如对讲机，是半双工通信，需要在不同时间内使用才能有效传递信息，即不同信号在不同时间传输。

同步时分复用 vs 统计时分复用

类型 说明 特点
同步时分复用（STDM） 每个信号源分配固定时隙，无论有无数据都占用 实现简单，但信道利用率低
统计时分复用（STDM） 时隙动态分配，仅当信号源有数据时才分配时隙 实现复杂，但信道利用率高
码分复用（CDM，Code Division Multiplexing）

码分复用为每个信号分配一个正交码。所有信号在同一时间、同一频率上传输，通过不同的编码序列在码域上相互区分。

就好像不同国家的学生同时在一个屋子里说话，有人在用中文，有人在用英语，有人在用法语交流…每个人只能听懂自己懂得的语言，听不懂的语言不会影响同语言交流。

码片序列（Chip Sequence）

在码分复用（CDMA）中，一比特会被再细分成多个码片（Chip）。码片是比比特更短的时间单位。

  • 每个比特由多个码片组成
  • 一个比特通常被分为 64 或 128 个码片
  • 码片序列越长，抗干扰能力越强，但占用带宽越大

在计算机网络中，每一个节点（站点）会被分配一个唯一的码片序列，用于区分不同的通信节点。

在计算机网络中，任意两个节点的码片序列是正交的，从而实现多用户共存且互不干扰

从数学角度看，所谓正交就是任意两个不同的码片归一化内积为0

码片序列的正交性：

设两个码片序列 $S$ 和 $T$ 的长度均为 $m$，若它们正交，则满足：

$$S \cdot T = \frac{S_1 T_1 + S_2 T_2 + \cdots + S_m T_m}{m} = 0$$

示例：两个码片序列 $A$ 和 $B$ 分别为

$$A = (-1 \quad -1 \quad -1 \quad +1 \quad +1 \quad -1 \quad +1 \quad +1)$$

$$B = (-1 \quad -1 \quad +1 \quad -1 \quad +1 \quad +1 \quad +1 \quad -1)$$

计算其内积：

$$A \cdot B = \frac{1 + 1 - 1 - 1 + 1 - 1 + 1 - 1}{8} = 0$$

因此，$A$ 和 $B$ 为正交码片序列。

任何码片与自身归一化内积一定为1。

码片序列的自相关性：

设码片序列 $S$ 的长度为 $m$，则其与自身的内积满足：

$$S \cdot S = \frac{S_1 S_1 + S_2 S_2 + \cdots + S_m S_m}{m} = 1$$

示例：码片序列 $A$ 为

$$A = \begin{pmatrix} -1 & -1 & -1 & +1 & +1 & -1 & +1 & +1 \end{pmatrix}$$

计算其自相关内积：

$$A \cdot A = \frac{1 + 1 + 1 + 1 + 1 + 1 + 1 + 1}{8} = \frac{8}{8} = 1$$

因此，码片序列与其自身的内积为 1。

任何码片与自身反码归一化内积一定为-1

码片序列与其反码的相关性：

设码片序列 $S$ 的长度为 $m$，$\overline{S}$ 为 $S$ 的反码（各位取反），则：

$$S \cdot \overline{S} = \frac{S_1 \overline{S_1} + S_2 \overline{S_2} + \cdots + S_m \overline{S_m}}{m} = -1$$

示例：码片序列 $A$ 及其反码 $\overline{A}$ 分别为

$$A = \begin{pmatrix} -1 & -1 & -1 & +1 & +1 & -1 & +1 & +1 \end{pmatrix}$$

$$\overline{A} = \begin{pmatrix} +1 & +1 & +1 & -1 & -1 & +1 & -1 & -1 \end{pmatrix}$$

计算 $A$ 与 $\overline{A}$ 的相关性：

$$A \cdot \overline{A} = \frac{-1 - 1 - 1 - 1 - 1 - 1 - 1 - 1}{8} = -1$$

因此，码片序列与其反码的内积为 $-1$。

码分复用中的数据恢复（解码）

在码分复用（CDMA）系统中，接收方必须预先知道发送节点的码片序列，才能正确恢复该节点发送的数据。这就是为什么每个节点都需要分配一个唯一的、已知的码片序列。

解码原理

接收端接收到的是所有节点信号的叠加信号。要恢复某个特定节点（如节点 A）发送的数据，接收端只需要：

  1. 用节点 A 的码片序列与接收到的叠加信号做内积运算
  2. 将内积结果除以码片长度进行归一化
  3. 根据结果判断节点 A 发送的是 1、0 还是静默

解码判断规则

归一化内积结果 含义
+1 该节点发送了比特 1
-1 该节点发送了比特 0
0 该节点没有发送数据（静默）

码分复用解码示例

两个节点的码片序列分别为：

$$A = \begin{pmatrix} -1 & -1 & +1 & -1 & +1 & +1 & +1 & -1 \end{pmatrix}$$

$$B = \begin{pmatrix} -1 & +1 & -1 & +1 & +1 & -1 & +1 & -1 \end{pmatrix}$$

发送数据

假设节点 A 发送比特 1，节点 B 发送比特 0：

$$\text{节点 A：} \quad A = \begin{pmatrix} -1 & -1 & +1 & -1 & +1 & +1 & +1 & -1 \end{pmatrix}$$

$$\text{节点 B：} \quad \overline{B} = \begin{pmatrix} +1 & -1 & +1 & -1 & -1 & +1 & -1 & +1 \end{pmatrix}$$

空中叠加信号

$$S_{\text{叠加}} = A + \overline{B}$$

$$S_{\text{叠加}} = \begin{pmatrix} 0 & -2 & +2 & -2 & 0 & +2 & 0 & 0 \end{pmatrix}$$

恢复节点 A 的数据

用节点 A 的码片序列与叠加信号做内积：

$$S_{\text{叠加}} \cdot A = \frac{0 + 2 + 2 + 2 + 0 + 2 + 0 + 0}{8} = \frac{8}{8} = 1$$

$$\text{归一化内积为 } +1 \quad \Longrightarrow \quad \text{节点 A 发送的是比特 1}$$

恢复节点 B 的数据

用节点 B 的码片序列与叠加信号做内积：

$$S_{\text{叠加}} \cdot B = \frac{0 - 2 - 2 - 2 + 0 - 2 + 0 + 0}{8} = \frac{-8}{8} = -1$$

$$\text{归一化内积为 } -1 \quad \Longrightarrow \quad \text{节点 B 发送的是比特 0}$$

差错控制——错误检测

数据在传输过程中，由于各种因素（如干扰、噪声、信号衰减），可能导致比特错误（比特翻转）。数据链路层提供错误检测机制，保证数据传输的可靠性，使得接收端能检测出数据并采取相应措施（如请求重传）。

奇偶校验（Parity Check）
  • 奇偶校验具体采用奇校验还是偶校验是发送方与接收方事先协商好的
  • 无论奇校验还是偶校验，判断的都是数据中1的个数是奇数还是偶数
  • 数据的1的个数 + 校验位数字 = 满足奇校验或偶校验的要求

例如发送数据为10110101，采用偶校验。八位数据中1的个数是5，则在后面增加一位校验位1来使1的总个数为6（偶数个）满足校验要求。

如果为奇校验，则末尾的检验为写0，满足1的个数为5个（奇数个）满足校验要求。

当数据不满足奇偶校验条件时重传

优点：实现简单，开销小

缺点：检测能力弱，只能检测奇数个比特的错误，偶数个比特错误无法检测。

  • 发送方将待发送的数据分成若干段（通常为16位一组）

循环冗余校验（CRC，Cyclic Redundancy Check）

CRC 是一种广泛用于数据链路层的错误检测方法，常用于以太网、HDLC、PPP 等协议。

  • 发送方和接收方事先约定一个叫作生成多项式的二进制序列
  • 生成多项式如果有 n 位，发送方在发送数据末尾添加 n-1 个 0
  • 发送方使用末尾添加 0 的数据除以生成多项式，得到的余数为 CRC 码
  • 发送方发送原始数据 + CRC
  • 接收端收到数据后，用同样的生成多项式去除。如果余数为 0，则数据无误；否则数据有误。

假设发送端情况如下：

原始数据：1011001

生成多项式：1101

生成多项式有4位，所以在原始数据后方加3个0（n-1个0）

然后做多项式除法：（主要用异或运算）

  1. 在CRC计算中，我们用的是一种特殊的“减法”，叫做模2减法。你可以把它想象成“按位比较”：如果两个位相同，结果为0；如果两个位不同，结果为1。这个过程不需要向高位借位，这是它和普通减法的最大区别。
  2. 对齐与初始异或：将参与计算的数据（末尾已补0）的最高位与生成多项式的最高位对齐，进行第一次模2除法异或运算。
  3. 结果处理：将本次异或的结果作为部分余数。
  4. 最高位检查：检查部分余数的最高位（即最左边的位）：
    • 若最高位为 1，则下一轮继续用完整的生成多项式（位数不变）与之进行异或。
    • 若最高位为 0，则下一轮用全0序列（位数与生成多项式相同）与之进行异或。
  5. “落位”操作：将原始数据中下一位数字“拉下来”，附加到部分余数的末尾，凑成与生成多项式相同位数的新数，然后回到步骤3，重复此过程，直到原始数据的所有位都被“拉下来”参与运算。

最终发送端发送的数据为原始数据 + CRC码：1011001110

接收方使用生成多项式验证数据是否正确，使用接收到的数据除以生成多项式

余数为0，说明数据正确无误

为什么1101叫做“生成多项式”？

CRC中的多项式实际上是“二进制多项式”

  • 多项式的系数只可能是0或1，而不可能是其他数字
  • 系数为1的项表示存在该项，系数为0表示不存在该项

例如：

$$x^3 + x + 1$$

如果这个式子作为生成多项式，展开后是这样的：

$$x^3 + x + 1 = 1 \cdot x^3 + 0 \cdot x^2 + 1 \cdot x + 1$$

取各幂次的系数即为1011

同样地，$x^4 + x^3 + x + 1$ 的生成多项式为11011

生成多项式式如何确定的？

生成多项式不是随机的，也不是根据数据临时决定的，是事先由协议规定好的，固定不变的

  • 每一种协议在制定之初就明确规定了使用的CRC生成多项式
  • 不同协议使用的生成多项式不同，且标准化
  • 发送端和接收端都按照协议规定使用相同的固定生成多项式进行计算

停止-等待协议（Stop-and-Wait）

发送方只有接收到Ack确认帧的时候，才会发送下一个帧。

在发送出去后直到接收Ack确认帧之间的时间叫做一个RTT。单程发送叫单程时延（RTT/2）

超时重传：发送方每发送一帧，就会为该帧启动一个定时器。若在定时器超时之前未收到接收方发来的确认帧（ACK），则判定该帧已丢失或出错，并重传该帧。

超时时间的设定通常略大于一个平均往返时间（RTT），并可根据网络状况动态调整，以避免因网络抖动导致不必要的重传。

信道利用率

信道利用率 $U$：在一个发送周期内，链路真正用来“发送数据帧”的时间占比。

$$U = \frac{T_f}{T_f + T_{\text{ack}} + \text{RTT}}$$

其中，数据帧发送时间 $T_f$ 为：

$$T_f = \frac{L}{R}$$

参数说明：

  • $L$ 为帧长（bit）
  • $R$ 为发送速率（bit/s）
  • $T_{\text{ack}}$ 为 ACK 帧发送时间（题目描述中可能会忽略此项）
  • RTT 为往返时延

ALOHA协议

诞生背景：1970年代，夏威夷大学用于远程岛屿之间的无线数据传输

核心问题：多个设备共享同一信道，如何协调谁来发送数据？

ALOHA协议比较简单粗暴。总结起来就是八个字**：完全随机，碰撞重传**

发送机制：

  • 节点一旦有数据就立刻发送，无需监听信道状态
  • 不关心其它节点是否在发送，属于“盲发”

冲突处理：

  • 节点会等待一段时间（随机退避）后再次尝试发送

理论最大信道利用率：

  • 约18.4%

由于ALOHA协议没有监听，所以很容易出现这种部分重叠的情况

于是ALOHA协议有了一个升级款

时隙ALOHA

  • 将时间划分“时隙”，节点只能在时隙开始时发数据
  • 冲突只能发生在同一个时隙内，不再有“部分重叠”，冲突概率降低
  • 理论最大信道利用率 36.8%
  • 要求各节点系统时间同步，增加了实现复杂度

CSMA/CD（CSMA with Collision Detection）

边发边听，发现冲突马上停止，并等待随机时间再试一次

节点不仅发送前监听，还在发送的同时持续监听，一旦听到有别的节点的数据与自己数据冲突，立即停下来。

边发边听，冲突即停，随机等待后重试。是以太网经典共享介质环境下的核心协议。

传播延迟

传播延迟就是数据或信号从发送节点传输到接收节点的时间。最大传播延迟就是最远两个节点之间信号传播的时间。它决定了在最坏情况下，发送节点得多久才能得知是否发生冲突

如图所示，AE之间传播的延迟就是最大传播延迟。

因为此协议采用边发边听的方式检测冲突，如果发送的帧太小，导致帧在收到冲突信号之前就已经发送完毕，则无法检测到冲突。

所以最坏情况下，发送节点需要两倍最大传播延迟才能得知发生了冲突。（A发送的数据马上抵达E时，E也发了一个数据。此时A从发送数据到接收到E的数据花费了2个最大传播延迟）（我们通常根据此结论计算最短帧长）

争用期（往返传播延迟）

争用期即为发送节点多久才能得知是否发生了冲突。最大传播延迟位T，则争用期为2T

最小帧长

最小帧长的目的，是保证数据帧发送所用的最短时间 ≥ 往返传播延迟

如果数据帧过小，那么碰撞发生之前监听就停止了，那么就无法检测冲突

$$\text{最小帧长} = \text{争用期(2T)} \times \text{传输速率}$$

退避时间

当多个节点同时发现冲突、同时停下后，如果都同时重新发送，一定再冲突所以设计了随机等待机制（退避），避免持续碰撞

$$ \text{退避时间} = \text{争用期(2T)} \times \text{随机数k}, \quad k \in [0,\ 2^n-1] $$

n 为重传次数，n 的值最大为 10，重传次数最多 16 次

无线网络与有线网络

在有线局域网中，当一个站发出一帧时，所有其他站都能接收到这个帧。

在无线局域网中，由于无线电传输范围有限，无法向所有的站传输帧，也无法接收来自所有其他站的帧。

在无线局域网中，相对于发送信号而言，接收到的信号可能很微弱，因此，在无线信道中进行冲突检测非常困难，硬件成本高。

隐藏站问题

站 B 在站 A 和站 C 的信号覆盖范围内，可以接收站 A 和站 C 的数据，由于竞争者离的太远而导致无法检测到潜在的竞争者，这个问题称为隐藏问题。

站 B 向站 A 传输数据，站 C 向站 D 传输数据。当站 C 侦听到该范围内有数据传输，为了避免冲突，站 C 暂停向站 D 传输数据。不过站 C 的结论是错误的。

带碰撞避免的 CSMA（CSMA with Collision Avoidance，CSMA / CA）

节点在发送数据之前监听无线信道，如果信号强度超过一定阈值则认为当前有其他节点在该信道上发送数据，此时随机等一段时间后再次监听。

如果检测到信道空闲，需要等到一个帧间间隔（InterFrame Space，IFS）之后再发送数据，在等待的时候保持监听。

DIFS（Distributed InterFrame Space）分布式帧间间隔：

  • 用于普通数据帧之间的间隔
  • 节点在发送数据帧之前，需要监听信道是否空闲，若信道空闲，则等待 DIFS 时间再发送

SIFS（Short InterFrame Space 短帧间隔）：

  • 用于控制帧（如 ACK、RTS / CTS 等）之间的间隔
  • SIFS 是最短的间隔，通常用于控制信道使用的帧。

EIFS（Extended InterFrame Space）扩展帧间隔：

  • 主要用于错误帧，例如接收到错误数据的节点在发送 ACK 前需要等待更长时间。

信道预约：

在发送数据帧之前，发送方首先广播一个 RTS（Request to Send）帧这个 RTS 帧能够被其范围内的所有站点侦听到（图中：A向自己的范围内广播自己要向B发送数据）

接收方收到RTS帧后，需要广播一个CTS（Clear to Send）帧作为应答。发送方收到CTS帧之后开始数据传输。

任何一个站若监听到 RTS 帧，这些站必须保持沉默，等待足够长的时间，以便发送站接收 CTS 帧。

尽管有了预约信道来预防碰撞，但是如果多个发送方同时发送 RTS 帧，这些帧将发生部突，从而丢失数据。发送方没有在期望的时间间隔内收到 CTS 帧，则判定发生冲突。发送方将等待一段随机时间后，再进行重试。

当链路中大部分主机都比较繁忙，多台主机同时发送数据频率高，如果采用随机访问的方式，发生冲突的概率会比较高，可以采用轮询访问

也就是说有令牌的主机才可以发信，大家轮流持有令牌，这样避免了冲突

以太网（Ethernet)

概念：以太网是一种具体的局域网通信协议标准，定义了物理层和数据链路层的实现方式。

传统局域网的局限性

广播风暴：在一个大的局域网中，广播消息会不停地传输，影响带宽和网络性能，导致网络拥堵。

安全问题：所有设备都在同一个广播域内，恶意设备可能会轻易地接收到其他设备的流量，存在安全隐患。

扩展问题：随着网络规模的扩大，增加设备时必须调整物理布线，这使得扩展变得困难且成本高。

虚拟局域网

“网络规模不断扩大，我们如何能够在不改变物理结构的情况下，提高网络的效率、增强安全性、简化管理，而且还能灵活扩展？”

将物理局域网（LAN）划分为多个逻辑上的子网，每个子网叫做一个 VLAN。VLAN 通过逻辑隔离设备，保证设备之间的通信可以被有效管理，同时不会受到物理位置的限制。

虚拟局域网的目标

隔离广播流量：减少广播消息在网络中的传播范围。

提高安全性：通过将不同部门或功能的设备划分到不同的 VLAN，可以有效隔离它们之间的通信，降低攻击的风险。

简化网络管理：即使设备不在同一位置，也可以通过 VLAN 分配到相应逻辑子网中。

提高网络性能：划分 VLAN 可以减少网络中的冲突和广播流量，提高网络的整体效率。、

如何划分虚拟局域网（VLAN）

最常用的方法是：根据交换机的端口来划分 VLAN 以太网交换机的接口分为两类：access 接口和 trunk 接口

access端口：接收帧后，根据预先分配好的 VID 值，给帧添加标签，然后判断交换机内其它端口分配的 VID 与帧中的标签 VID 是否一致，如果一致则转发，否则不转发。

trunk接口：一般用于交换机之间的互联

广域网

广域网通常指覆盖范围很广的长距离网络，通常连接不同地区的城域网或者局域网，用来实现远距离通信。

广域网中数据链路层使用的是点对点信道，主要使用的协议有 PPP、LCP、NCP

PPP协议

PPP（Point to Point Protocol）协议：用于点对点的数据链路中，为通信双方建立点对点的连接。PPP 协议只支持点对点全双式链路的数据链路层协议

  • 将 IP 数据报封装到串行链路中，这部分信息长度小于 MTU（0～1500）
  • 链路控制协议（Link Control Protocal, LCP）：用于建立、配置和测试链路的连接
  • 网络控制协议（Network Control Protocal, NCP）：用于支持不同网络层协议（如 IPv4、IPv6）的配置和协商。

PPP协议数据帧格式

发起连接：PPP 连接通过链路控制协议（LCP）进行协商，双方交换链路参数并通过认证。

数据传输：PPP 数据帧根据网络层协议（如 IPv4）进行封装，并通过点对点链路传输。

网络层数据传输方式

无连接服务

定义：每个数据包（数据报）都是独立的，彼此之间没有任何关联。每个数据包携带了足够的信息，以便能够独立地从源地址传输到目的地址。没有事先建立连接，也不需要维护连接状态。在这样的环境中，数据包通常被称为数据报，这种网络通常被称为数据报网络。

特点：

  • 无需建立连接：发送方和接收方之间不需要建立连接，数据包可以直接发送。
  • 每个数据包独立：每个数据包都有完整的目的地址和路由信息，发送和接收的数据包之间没有任何关联。
  • 不保证可靠性：由于每个数据包是独立的，网络层不保证数据包的可靠传输，数据包可能丢失、乱序或者重复。
  • 适用场景：适用于那些对实时性要求高且可以容忍丢包的应用，如视频会议、实时游戏等。
有连接服务

定义：发送方和接收方在数据传输之前需要通过网络建立一条虚拟的通信路径（虚电路），所有数据包通过这条虚电路进行传输。虚电路在通信过程中始终存在，直到通信结束。这种网络称为虚电路网络。

特点：

  • 建立连接：发送方和接收方在数据传输前必须进行连接建立，通过建立虚拟电路来保证数据传输能够按照特定的顺序到达接收方。
  • 可靠传输：在虚电路网络中，数据包的顺序和完整性都能得到保证，网络层会对数据包进行确认和重传。
  • 固定路径：所有的数据包都会沿着同一路径传输，这样便于提供高效的流量控制和错误检测。
  • 适用场景：适用于对可靠性要求高、数据顺序需要保证的应用，如文件传输、电子邮件等。

路由与转发

路由（Routing）：指的是在网络层（主要是IP层）选择数据包从源到目的地的最佳路径的过程。路由涉及到路由表的维护和更新，通常由路由协议动态计算。

转发（Forwarding）：是指在路由选择已经完成之后，设备（如路由器）将数据包从一个接口转发到另一个接口的过程。转发的速度要求非常高，因为它直接影响到数据包的传输效率。

跳帧算法

跳帧算法（Hop-byHop Routing）是数据包从源节点传送到目的节点过程中，每一跳由各个路由器独立决定下一跳路由器的转发行为。这种转发行为基于路由表中的信息，每个路由器仅根据目标地址和自己的路由表做出转发决策。它并不需要全局网络信息，只需要局部的信息。这里就是下一跳中跳的说法来源。

路由算法

静态路由算法

定义：静态路由是由网络管理员手动配置的固定路由。路由器的路由表不会根据网络状态变化而自动调整，需要手动修改配置。

优点 简单：配置容易，适用于小型、简单网络。 控制性强：管理员可以精确控制数据包的路由路径。

缺点 不灵活：如果网络拓扑发生变化，必须手动重新配置。 扩展性差：随着网络规模扩大，静态路由配置变得难以维护。 对网络故障的应对能力差：如果某条路由失效，管理员必须手动修改路由表。

动态路由算法

定义：动态路由是通过路由协议自动计算并更新路由表的方式。路由器通过与其他路由器交换信息来学习和选择最佳路径，动态调整路由。

优点

自动化：动态路由协议能够根据网络拓扑变化自动调整路由，减少人工干预。

适应性强：适合中大型网络，能够根据网络状态变化动态调整路由。

故障恢复能力强：当某条路径发生故障时，路由协议能够快速计算出新的路径。

缺点

配置复杂：需要配置和管理路由协议，可能涉及较复杂的路由策略。

网络负载：动态路由协议会定期交换路由信息，这可能增加网络负载。

可能会发生路由环路等问题，需要谨慎配置。

距离向量路由算法

每个路由器（节点）维护一个路由表，路由表中有到达其他路由器的最短路径及到达那里使用的链路。通过定期与邻居交换路由表信息，更新自己的路由信息，最终每台路由器都了解到达目的地的最佳链路。

要素 说明
谁交换信息？ 仅与直接相连的所有邻居交换
交换什么？ 自己的整个路由表（即“我到各个目的地的距离”）
何时交换？ 定期（如每30秒）或在路由表发生变化时
工作过程 动作
1. 初始化 我认识谁？直连邻居的距离是多少？
2. 定期广播 每隔一段时间，把我的路由表发给所有邻居
3. 收到邻居信息后 把邻居的距离 + 我到邻居的距离，算出一个新值
4. 更新路由表 如果新值比原来的小，就更新；否则保持不变
5. 重复 直到没有变化为止（收敛）

最短路径 = min(邻居告诉我他到X的距离 + 我到该邻居的距离)

链路状态路由算法

每个路由器通过“广播”自己与邻居的链路状态（如带宽、延迟）给全网；

所有路由器最终都构建出相同的网络拓扑图；

每个路由器用Dijkstra算法计算出到各节点的最短路径 → 路由表。

工作流程 动作 说明
第一步：发现邻居 每个路由器通过发送Hello报文，发现与自己直连的邻居路由器。 类似于“打个招呼，确认对方在线”
第二步：测量距离 测量到每个邻居的链路代价（如带宽、延迟、跳数等） 代价可以是带宽倒数、延迟时间等
第三步：构建LSA 将“邻居 + 代价”信息封装成链路状态通告（LSA） 例如：A的LSA = {B:1, C:2}
第四步：泛洪广播 将LSA广播给网络中所有其他路由器（洪泛法） 每个路由器收到后，再转发给邻居，最终全网收到
第五步：构建拓扑图 每个路由器收集所有LSA后，构建出全网完整的拓扑图 所有路由器的拓扑图是一致的
第六步：计算最短路径 每个路由器独立运行Dijkstra算法，算出到所有节点的最短路径 计算结果填入路由表

路由器到达邻居的成本可以自动设置，也可以由网络运营商配置

  • 成本与链路带宽成反比，高容量带宽的路径成为路由更好的选择

    以太网 1 Gb/s 成本度量 1 以太网 100 Mb/s 成本度量 10

  • 如果网络在地理位置上分散，则链路的延迟可以作为成本的组成部分

路由器之间可以发送Echo指令测量RTT，以此作为成本的度量

一旦收集到交换需要的信息，每台路由器下一步的工作就是构建一个包含所有这些数据的包

数据包：发送方标志符、序号、年龄（age）、邻居列表和成本

泛洪（洪泛 flooding）把数据包发给全网

抑制泛洪：让路由器跟踪已经泛洪过的数据包，从而避免第二次发送。可以让源路由器在接收到来自主机的每一个数据包中放置一个序号，通过记录序号避免再泛洪出去

  • 如果是一个新数据包，使用泛洪进行转发
  • 如果是一个重复的数据包，则将它丢弃
  • 如果数据包的序号小于当前已观察到的最大序号，则将该数据包当作过时数据包拒绝接受

计算路径生成路由表

当一台路由器收到了全部的链路状态数据包之后，就可以构造完整的网络图，路由器本地运行 Dijkstra 算法，从而构造出从本地出发到所有可能目标的最短路径

  • 算法的结果信息存放路由表中，根据这个信息，路由器就可以知道数据包使用哪条链路可以尽快到达目的地
  • 与距离向量路由算法相比，链路状态路由算法需要更多的内存和计算量，对于大型网络而言，仍然是一个问题。不过链路状态不再受慢收敛问题的影响。

RIP（Routing Information Protocol，路由信息协议）

RIP 是一种基于距离向量（Distance-Vector）算法的内部网关协议，以**跳数（Hop Count）**作为度量标准来衡量到达目的网络的距离。数据包每经过一个路由器，跳数加 1。

核心机制：

  • 跳数限制：最大跳数为 15，跳数达到 16 即被视为不可达，以此防止路由环路无限循环。
  • 路由交换：相邻路由器之间每隔 30 秒 定期交换完整的路由表信息。
  • 超时失效：若长时间未收到某条路由表项的更新信息，该表项将被标记为无效。
  • 路由表结构：包含三个关键字段——目的网络、跳数、下一跳 IP 地址。

特点与局限：

  • RIP 协议工作在应用层，基于 UDP 进行报文封装和传输。
  • 适用于小规模网络（跳数限制 15 决定了其网络直径有限）。
  • 每 30 秒的周期性广播会占用大量带宽，在大规模网络中效率低下。
  • 存在 “好消息传播快，坏消息传播慢” 的收敛问题，可能导致短暂的路由环路。

OSPF（Open Shortest Path First，开放式最短路径优先）

OSPF 是一种基于链路状态（Link-State）算法的内部网关协议，是 RIP 的升级替代方案。

核心机制：

  • 代价度量：与 RIP 以跳数为度量不同，OSPF 的代价（Cost）基于带宽、时延、MTU等因素综合计算，能更真实地反映链路质量。
  • 链路状态通告：路由器通过交换链路状态信息，构建全网拓扑图，并利用 Dijkstra 最短路径算法计算出最优路由。

特点与优势：

  • OSPF 协议工作在网络层，数据直接封装在 IP 分组（协议号 89）中进行传输，无需依赖 UDP 或 TCP。
  • 支持负载均衡，可将流量分散到多条等价路径上，提高链路利用率。
  • 支持分层结构（区域划分），适用于大规模网络场景，网络直径不受跳数限制。
  • 路由更新采用触发更新机制，网络拓扑变化时只发送变化部分，收敛速度快。

BGP（Border Gateway Protocol，边界网关协议）

BGP 是互联网中唯一使用的外部网关协议（EGP），用于在不同自治系统（AS）之间交换路由信息。

核心机制：

  • 路径向量算法：BGP 基于路径向量（Path Vector）算法，不仅记录到达目的网络的路径，还包含经过的完整 AS 路径列表，从而有效防止路由环路。
  • 策略路由：与 RIP、OSPF 仅基于网络性能（跳数、带宽等）选择路径不同，BGP 的路由选择决策通常会综合考虑政治、安全、经济及管理策略等因素（如“不经过某国运营商”“优先选择商业伙伴的链路”）。

特点与优势：

  • BGP 协议工作在应用层，基于 TCP 协议（端口号 179）封装报文，保证了路由信息传输的可靠性。
  • 超强承载能力：OSPF 通常支持约一万条路由条目，而 BGP 可以承载十万条以上的路由条目，适用于大型跨域网络（如国家级骨干网、全球互联网）。
  • 支持丰富的路由属性和细粒度的路由策略控制，是互联网服务提供商（ISP）之间互联的核心协议。

IP数据报

分组/IP分组/IP数据报/IP数据包 这几个名词是同一个东西。

IP数据报格式（IPV4）

IP数据报包含首部和数据两个部分

版本：规定了数据报的 IP 协议版本，通过版本号，路由器能确定如何解释 IP 数据报的剩余部分。

首部长度：表示 IP 数据报首部长度（以 4 字节为单位）。该字段取值范围 5～15（0101～1111），大多数 IP 数据报不包含选项，所以一般 IP 数据报首部是 20 字节。

服务类型：前 6 位用来表示数据报的服务类型，后 2 位用来携带拥塞通知信息，配合 TCP 实现端到端拥塞管理。

数据报长度：整个 IP 数据报（头部 + 数据）的长度，单位字节。IP 数据报理论最大长度是 65535 字节，但很少有超过 1500 字节的。

标志：唯一标识一个原始数据报，用于分片与重组。当一个大的数据报被分片后，各分片都带相同的标识值，以便目的端正确重组。

第一位：保留位，必须为 0

第二位：DF（Don’t Fragment，不分片），置 1 为不分片

第三位：MF（More Fragments，后续还有分片），除最后一片外的所有分片，MF=1；最后一片 MF=0

片偏移量：当前分片在原始数据报中的位置，单位为 8 字节。重组时，目的端根据偏移值把各片按正确顺序拼回原始数据

生存时间：用于限制数据报生存时间的计数器，最初是以秒计数，最大生存时间为 255s。

现在是跳计数器，每经过一个路由器，计数器减 1，当减到 0 时，数据报被丢弃。这样做的意义在于防止循环转发导致数据报在网络中"无限存活"。

上层协议：该字段当一个 IP 数据报报到达最终目的地时才会有用。该字段的值指示了 IP 数据报应该交给哪个特定的传输层协议。例如，1 = ICMP，6 = TCP，17 = UDP 等。

首部校验和：用来检验数据报的首部，不包括数据部分，接收端验证头部在传输过程中是否出错，若不匹配则丢弃数据报。

选项：提供额外功能，如安全级别、安全路由记录、时间戳等，一般不用。

IP地址

IP 地址（Internet Protocol Address）是网络中每台设备的唯一标识符，类似于一个"门牌号"，它由 32 位二进制数组成，网络中每一台主机和路由器都有一个 IP 地址，一个 IP 地址并不是指向一台主机，而是一个网络接口。

绝大多数主机都在一个网络中，所以只有一个 IP 地址，而路由器有多个接口，所以有多个 IP 地址。

将一个地址块划分成几部分，将一个大的网络分割成多个小的子网，供多个内部网络使用，但对于外部世界仍然像单个网络一样。这样可以更好地管理和利用地址空间，避免浪费。

ICMP协议

ICMP（Internet Control Message Protocol，网络控制消息协议）

当路由器正在处理一个数据包的过程中有意外事情发生时，可通过 ICMP 向发送方报告。

场景举例：

目标主机不可达：客户端访问服务器超时，却不知到底是目的主机挂掉还是路由断链？

TTL 超时：数据包在网络环路中陷入"无限转发"？

路径探测：如何知道数据包经过了哪些中间路由？

ping

发送 ECHO（回显）到目的地址，判断目的地址的设备是否还“活着”，如果目的地址回复 ECHO REPLY（回显应答），说明还“活着”，或者检测自己有没有接入网络。

这里的Ping指令，TTL代表着生命周期。TTL默认值是64，每经过一跳就减少1。这里TTL=52说明经过了12跳到达目标。如果TTL减少到0，则会被丢弃，并由ICMP报告

traceroute

给目标发送一系列的数据包，分别将 TTL 设置为 1, 2, 3, ⋯，这些数据包的 TTL 数值沿着路径在后续的路由器上到达 0，这些路由器各自送回一个超时消息给主机，利用这种技巧，可以确定沿途路由器的 IP 地址。

这样就能通过超时的超时信息获取到沿途路径上每一个路由器的地址

DCHP协议

DHCP（Dynamic Host Configuration Protocol）动态主机配置协议

当一台新主机接入网络时，它会通过广播形式发送 DHCP DISCOVER 消息，用于搜寻可用的 DHCP 服务。该广播消息仅能被 DHCP 服务器识别并响应，网络中的其他无关主机则会将其忽略。DHCP 服务器在收到此请求后，会回复一条 DHCP OFFER 消息，其中包含一个可供该主机使用的 IP 地址及其他网络配置参数。

若当前局域网内没有部署 DHCP 服务器，也无需担心。网络管理员可以通过配置 DHCP 中继代理（Relay Agent），将主机的 DHCP 请求跨网段转发至其他子网中的 DHCP 服务器，从而实现跨网络的统一 IP 地址分配与管理。

ARP协议

ARP（Address Resolution Protocol）地址解析协议

背景：以太网中，网络层用 IP 地址找到目标主机，但链路层需要 MAC 地址才能发送帧

作用：在同一局域网内，通过 ARP 将基于目的 IP 地址找到对应的 MAC 地址

C2会以单播的形式告诉C1自己的MAC地址。

那么如果C1要询问C6的MAC地址该怎么办？

网关（Gateway）：是指连接不同网络、负责转发数据包的网络设备或路由器接口，它是网络边界的出入口。

他需要写上C6的IP地址，依旧广播给局域网。于是网关收到了这个消息，把自己的MAC地址给C1。

于是C1给C6发信时，目的IP地址是C6的IP地址，目的MAC地址是C3的MAC地址。

在经过网关时，网关会将目的MAC地址换成C6的MAC地址（基于ARP协议）。

TCP全双工通信

三次握手

初始序号（ISN, Initial Sequence Number）是随机生成的，而不是从 0 或 1 开始。这主要是出于安全考虑（防止序号预测攻击）和避免历史混淆（防止旧连接的残留数据包干扰新连接）。

TCP 是全双工通信，没有固定的发送端和接收端之分。一旦连接建立，两端均可同时收发数据。三次握手过程中，客户端和服务端各自独立选择一个随机起始序号（x 和 y），并通过 SYN 包告知对方，这正是全双工通信的体现——双方都需要序号来组织自己发送的数据流。

当 SYN 标志位被置为 0 时，表示当前报文段 不是用于发起或接受新连接。

双方主机在不同阶段有不同的状态。

ack确认号

ack为被期待的下一个包的序号。传输的数据长度data_len也占用序号空间。

释放连接

终止一个连接有两种方式：非对称释放和对称释放

非对称释放：电话系统的工作方式，一方挂断，连接中断

对称释放：把连接看成是两个独立的单向连接，要求每一个单向连接被单独释放

TCP需要对称释放。

四次挥手

主机1进入到TIME-WAIT状态后，会等待2MLS的时间。这是为了避免最后一条ACK的消息主机2没有收到。那样的话，主机2会重发上一条FIN=1的消息，于是主机1再重发一次。过了2MSL的时候，无论主机2有没有收到第四次挥手的消息，主机1都会进入CLOSED状态。

最大数据包生存时间

MSL（Maximum Segment Lifetime）

MSL 表示任意 TCP 报文在网络中可能存在的最长生存时间（一般取 2 分钟或 30 秒，具体实现可不同）。

TCP流量控制

为什么需要流量控制？

当发送方的发送速率超过接收方的接收能力时，接收方的缓冲区会被填满，后续到达的数据将因无法存储而被丢弃，进而触发不必要的重传，浪费网络带宽。流量控制的目的，就是让发送方根据接收方的实际处理能力来调整发送速度，避免“发送太快，接收来不及处理”的情况。

TCP 如何实现流量控制？

TCP 采用**滑动窗口（Sliding Window）**机制来实现流量控制。接收方通过通告窗口大小（rwnd，即接收缓存剩余空间）来告知发送方“你还能发多少数据”。

  • 接收缓存的大小取决于操作系统为 TCP 连接分配的缓冲区空间。
  • 发送窗口的大小由接收窗口（rwnd）决定，即**：发送窗口 = min(拥塞窗口 cwnd, 接收窗口 rwnd)**。在仅考虑流量控制时，可以认为发送窗口的大小等于接收窗口。

与数据链路层滑动窗口的区别

对比维度 数据链路层（如 HDLC） 传输层（TCP）
窗口大小 固定（由帧序号位数决定） 动态调整（由接收缓存剩余空间决定）
调整依据 协议约定 接收方实时的缓冲区状态

TCP拥塞控制

流量控制考虑主机2能收多少，拥塞控制考虑的是传输链路上是否拥堵。

那么我们发送窗口到底是遵循cwnd还是rwnd呢

发送窗口大小由拥塞窗口和接收窗口共同决定：

$$\text{swnd} = \min(\text{cwnd}, \text{rwnd})$$

我们这里先假设接收窗口无限大。

发送方维护一个叫做拥塞窗口cwnd有状态变量，其值取决于网络的拥塞程度，并且动态变化。

cwnd维护原则：只要网络没有出现拥塞，cwnd就再增大一些，但只要网络出现拥塞，cwnd就减少一些。

判断出现网络拥塞的依据：没有按时收到应当到达的确认报文（即发生超时重传）。

以TCP报文段的个数为单位，而不是以字节为单位

慢开始门限值sst（slow-start-threshold）：慢开始算法的阈值。

cwnd<sst，使用慢开始算法

cwnd=sst，既可以使用慢开始算法，也可以使用拥塞避免算法。

cwnd>sst，停止使用慢开始算法而改用拥塞避免算法

慢开始

假设最初时慢开始门限值为16，拥塞窗口在慢开始门限值之前指数增加。在慢开始门限值后线性增加。

如果我们在cwnd=24时发生了超时，于是将sst修改为发生拥塞时cwnd窗口的一半，然后将cwnd的值减小到1，并按照之前的规则进行慢开始。

快重传和快恢复

TCP Tahoe版本已被废弃，现使用TCP Reno版本进行快重传和快恢复

快重传是指使发送方尽快进行重传，而不是等超时重传计时器超时再重传。

  • 即使收到了失序的报文段也要立即发出对已收到报文的重复确认；
  • 发送方一旦收到3个连续的重复确认，就将相应的报文段立即重传，而不是等该报文段的超时重传计时器超时再重传。

和TCP的快速重传类似。发送方连续接受三个重复确认，则立即重传该数据报。同时也会累计确认。

快恢复是指发送方一旦收到3个重复确认，就知道现在只是丢失了个别报文段，于是不慢开始算法，而是执行快恢复算法。

  • 发送方将ssthresh值和cwnd值调整为当前cwnd的一半，开始执行拥塞避免算法。

  • HTTP：一个简单的请求-响应协议，客户端发请求，服务器回响应。无状态，每个请求独立。
